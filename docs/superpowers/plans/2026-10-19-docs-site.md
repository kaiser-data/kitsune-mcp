# Docs Site and Homepage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a homepage and documentation site for Kitsune MCP on GitHub Pages and point PyPI, npm, the MCP Registry and the repo at it.

**Architecture:** MkDocs Material builds `docs/` into a static site. The homepage is `docs/index.md` rendered through a custom template `overrides/home.html`; every other page is a refined existing Markdown file. A GitHub Actions workflow builds with `--strict` and deploys to Pages on push to `main`.

**Tech Stack:** mkdocs-material 9.x (pulls mkdocs 1.6), pymdown-extensions (tabs, snippets, superfences), GitHub Actions (`actions/upload-pages-artifact`, `actions/deploy-pages`), uv dependency groups.

Spec: `docs/superpowers/specs/2026-10-19-docs-site-design.md`

## Global Constraints

- Site URL: `https://kaiser-data.github.io/kitsune-mcp/`
- Dependencies only in `[dependency-groups] docs` of `pyproject.toml`; `[project] dependencies` unchanged.
- Not published: `docs/internal/`, `docs/superpowers/`, `docs/article.md`, `docs/demo-script.md`, `docs/demo-realtime.md`.
- Demo GIF referenced as `https://raw.githubusercontent.com/kaiser-data/kitsune-mcp/main/docs/demo-hot-reload.gif`.
- Lean tool profile (default): `status, search, auth, shapeshift, call, auto, connect, release, reload`. All others need `KITSUNE_TOOLS=all`.
- Pitch line, verbatim: "Let your agent test the MCP server it's building."
- `uv run mkdocs build --strict` must pass; `uv run pytest -q` and `ruff check . && ruff format --check .` must stay green.
